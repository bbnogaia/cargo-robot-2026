Requirements




In the picture above:

• The slots1-4 depict the hold areas reserved to store one container each,

• The slot5 depicts an area, where the cargorobot must temporarily store a container, before to place it in one of the
  slots1-4. During temporary storage, a 'marker' device labels the container with an identification barcode and signals when this marking
  activity is completed.

The company asks us to build service named cargoservice that should work as follows.

The cargoservice is able to receive a request to load a container sent by some customer by using the pushbutton of the IOPort.

• It sends the answer retrylater, if the IOPort is currently occupied by a container or if the system is Out of service

• It rejects the request when the hold is already full, i.e. the slots1-4 are already occupied.

• Otherwise, it considers the system as engaged, detects a free slot and returns as answer the name of such a reserved slot.
  While engaged, the system must blink a Led.

When the request to load is accepted, the customer must move the container in the sensor area within prefixed amount of time (e.g. 30
secs), otherwise the systems becomes disengaged. Then, the cargoservice uses the cargorobot to move the container from the
IOPort to the slot5 (for marking the container) and then to the reserved slot.

The service must also show on the display on the IOPort:

• the current state of the hold

• the message 'Service working', when it is all is going well

• the message 'Out of service' if the sonar sensor measures a distance D > DFREE for at least 3 secs 
  (perhaps a failure of the sonar).

Dettaglio di cargoservice:

• cargoservice accetta richieste di carico tramite la seguente sintassi:

  •  cargoservice ↔ client (webgui-ioport)
  
    Request requestToLoad : requestToLoad(NOARGS)
    Reply loadAnswer: loadAnswer(ANSWER) for requestToLoad
  

• cargoservice coordina i movimenti del cargorobot e si interfaccia con il software del committente, adattandosi ai suoi formati di messaggistica.
Si evidenziano i più rilevanti:

  •  cargoservice ↔ cargorobot (robotsmart26)
 
    Request moverobot : moverobot(TARGETX, TARGETY, STEPTIME)
    Reply moverobotdone : moverobotdone(ARG) for moverobot 
    Reply moverobotfailed: moverobotfailed(PLANDONE, PLANTODO) for moverobot 
 

• cargoservice sarà in grado di gestire e percepire lo stato corrente del sistema tramite il modulo sviluppato nello Sprint0 (cargoHold-1.0.jar).

• Come richiesto dal committente all'avvio del sistema tutti gli slot risulteranno liberi.

• Notiamo che cargoservice, essendo configurato come un QActor (Qak), presenta una propria coda locale in cui sono
  depositati i messaggi a lui inviati da altri attori. Per capirne bene le conseguenza è possibile affidarsi alla documentazione Qak.  

Assegnazione slot e carimento del container in stiva:

• Una volta ricevuta la richiesta di carico, se ogni condizione presentata nei requisiti è soddisfatta,
  cargorobot si reca presso l'IOPort e in un tempo stimato di 2 secondi recupera il container.


     State moveToIOPort {
        println("$name | Container rilevato! Comando cargorobot verso IOPort in coordinate ($IOPortX, $IOPortY)") color magenta
        request robotsmart -m moverobot : moverobot($IOPortX, $IOPortY, 330)
    }
    Transition t2
        whenReply moverobotdone -> moveToSlot5
        whenReply moverobotfailed -> handleRobotFailure

    State moveToSlot5 {
    	delay 2000
        println("$name | IOPort raggiunta. Comando cargorobot verso slot5 (marcatura) in coordinate ($Slot5X, $Slot5Y)") color magenta
        request robotsmart -m moverobot : moverobot($Slot5X, $Slot5Y, 330)
    }
    Transition t3
        whenReply moverobotdone -> markContainer
        whenReply moverobotfailed -> handleRobotFailure


• cargorobot raggiunge lo slot5 dove avverrà la marcatura del container in un tempo stimato di 3 secondi.


     State markContainer {
        println("$name | container allo slot5. Attesa marcatura barcode...") color magenta
        delay 3000 
    }
    Goto moveToFinalSlot


• Infine, raggiunge lo slot assegnato e rilascia il container.
